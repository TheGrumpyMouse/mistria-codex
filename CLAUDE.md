# Mistria Codex

Unofficial companion PWA for Fields of Mistria. Static site on GitHub Pages, offline-first, no accounts.

The plan lives in `docs/PLAN.md`. Read it before starting anything non-trivial.

---

## Hard rules

These are not style preferences. Breaking one either creates legal exposure or silently corrupts the dataset.

### 1. No in-game text, no wiki prose. Game art only under `assets/game/`

- **Never fetch `Items.description`** from the wiki. It is verbatim in-game text. The Cargo fetcher's `fields=` list must not contain it. Not-fetching is the control; stripping-after-fetching is not.
- **Never copy wiki prose.** Use the wiki to verify facts, then write your own words.
- **Never hotlink wiki images.** Every sprite is served from our own origin.
- **Game art lives in `assets/game/` and nowhere else, and only if `assets/game/manifest.json` lists it.** An image anywhere else still fails the build, and an unmanifested file under `assets/game/` fails it too.

The art rule is narrower than it used to be; **the text rules are not.** The amendment covers pixels, not prose — see [docs/DATA-POLICY.md](docs/DATA-POLICY.md) for the policy we operate under and what it does and does not buy us.

**The single-directory rule is the whole point.** `git rm -r assets/game && pnpm build:ship` is the complete takedown procedure. If a change makes that untrue — a sprite copied elsewhere, an asset path baked into `data/`, an image inlined as base64 — that change is a bug regardless of how well it works.

For the same reason, **`data/` never references a game asset.** The `icon_key` → sprite mapping exists only in the manifest, so deleting `assets/` orphans nothing.

**And the one that looks like compliance but isn't: do not paraphrase an in-game description into a `blurb`.** A paraphrase of a short creative sentence is still a derivative work. It does exactly what this rule exists to prevent, while appearing to follow it. Write facts — where it's found, what it's used for, what it's worth — or write `null`. Most items don't need a blurb at all.

Factual numbers (sell value, growth days, seasons, drop rates, coordinates) are fine and are the point of the project.

`writeJson()` throws on denylisted keys and CI fails on long strings, but those catch accidents, not judgement.

### 2. Do not invent data

An empty field is correct. A plausible guess is a bug that propagates into the dataset and becomes nearly impossible to find later.

If a value isn't in a source: emit `null` and add the field name to `data_gaps[]`. This applies during refactors too — do not "helpfully" fill a gap you noticed.

Unresolved tokens go to `build/unresolved.json` and fail the build under `--strict`. **The build failing on an unrecognised token is the design working**, not a bug to route around.

### 3. Never use numeric item IDs as keys or foreign keys

They change between game patches. Internal snake_case names are the keys, always. `numeric_id` is a nullable, version-stamped secondary field and nothing may reference it.

Most item ids **are** the game's own names — Copper Ore is `ore_copper`, a Chicken Egg is `egg`. 192 of 999 differed from the naive slug, which is the measure of how undetectable this error class is. See `build/reports/id-divergence.md`, written by `pnpm validate`.

G1 ran, and **the game agreed with the v0.15.0 snapshot on every single name**, so no id moved. 1,015 of 1,154 are now `confirmed` — read from the installed build. The residual 139 are almost all animal cosmetics, which the wiki calls items and the game does not: they live under `[cosmetics.*]` in `ranching/animals/`, outside the `ItemId` enum, and nothing will ever confirm them.

The game assigns numeric ids as **enum ordinals at compile time**, so inserting one item shifts every id after it — NPC Studio's own SDK says so, and [docs/game-file-extraction.md](docs/game-file-extraction.md) cites it.

Compute an item id with `ctx.idFor(displayName)`, never `toSnakeId` — the index lives behind that one function, so an id that changes changes everywhere at once. Slugifying locally is how half a dataset ends up pointing at names the other half abandoned.

### 4. Respect the three data tiers

| Directory | Written by | Never |
|---|---|---|
| `sources/wiki/` | generated by `enrich:*` | hand-edited |
| `sources/game/` | generated by `extract` | hand-edited |
| `curated/` | hand-authored by humans | generated |
| `data/` | generated by `build:data` | hand-edited |
| `assets/game/` | generated by `assets:fetch` | hand-edited, or referenced from `data/` |

**Editing `data/` directly is the most likely wrong move here** — it's committed, pretty-printed, and looks editable. It isn't. `data/` is a pure deterministic function of `sources/ + curated/`, and CI enforces that by regenerating and running `git diff --exit-code`. To change something in `data/`, change its input.

`apps/web/public/data/` is build output and gitignored.

## Verified API facts

Confirmed live. Don't re-derive these.

The wiki's Cargo API works, but **only via `Special:CargoExport`**, and **fields must be table-qualified**:

```
https://fieldsofmistria.wiki.gg/index.php?title=Special:CargoExport
  &tables=GiftPrefs&fields=GiftPrefs.charName,GiftPrefs.itemName,GiftPrefs.interest
  &limit=500&offset=0&format=json
```

`api.php?action=cargoquery` returns `MWException`. Unqualified fields return `No field named "x" found`.

| Table | Rows | Fields |
|---|---|---|
| `Items` | 1154 | itemName, ~~description~~, icon, sources[], location[], season, isCraftable, isBuyable, isConsumable, sellValue, health, stamina, mana, museum, tags[] |
| `GiftPrefs` | 5328 | charName, itemName, interest |
| `Fish` | 143 | fishName, rarity, size, weather[], fishing, diving |
| `Bugs` | 103 | name, rarity, weather[], season[], time, spawnCondition, museumSet |
| `Crops` | 58 | name, seed, growthTime, regrowTime, museumSet |
| `Characters` | 56 | charName, relatives, affiliation, occupation, relationship, romanceable, birth, species, gender, eyes |
| `Artifacts` 110 · `ArtifactComments` 101 · `Recipes` 282 · `Ingredients` 663 · `FurnitureTEMP` 773 · `SortOrders` 6 |

Three consequences:

1. **`Fish` has no season, location, or time.** They come from `Items`, joined on **display name**. Assert `Items.itemName` is unique or the join is silently wrong.
2. **Time data barely exists.** Only `Bugs.time`, and it's loose text. Hence "unknown does not exclude" (below).
3. **Not in Cargo at all:** NPC schedules, museum set groupings, forageables as a category, festivals, quests, shops, mines, skills, animals, buildings, locations. Hand-curated or page-parsed.

**Map coordinates are not in Cargo either — they are in the `Map:` namespace.** The wiki runs the DataMaps extension, so its maps are JSON pages: `Map:V0.13 (Unlocked)` declares a `0 0 5442 3599` space and 46 markers, each naming the article it belongs to. `crs.bottomRight` is `[height, width]` and a marker's `lat`/`lon` are **y and x** in that order — the names are borrowed from a mapping library and are not meant literally. Read them the other way round and every pin is silently somewhere else.

Only that one map is usable. The per-region pages (`Map:Town` and friends) have zero markers and declare a space that does not match their own background image — they are stubs, and reading them produces confident nonsense.

Pagination is real: page with `&offset=N&limit=500` until a page returns fewer rows than the limit. A zero-row response must **throw**, never write — "empty response overwrites good data" is the classic failure here.

## Verified game-file facts

From `sources/game/`, which is committed. Don't re-derive these either.

**`false` means unrestricted, not empty.** `weather = false` on a fish means it bites in *every* weather. Read literally it says the opposite, and the record would be confidently wrong.

**Hours run past 24.** `hours = [20, 26]` is 20:00–02:00, because the game day ends at 02:00. Clamping to 24 deletes the whole night window.

**The game has four weather classes, not six states** — `calm`, `inclement`, `heavy_inclement`, `special` — and the season decides what each looks like. `heavy_inclement` is a thunderstorm in fall and a blizzard in winter. The mapping and its reasoning live in `curated/vocab/weather.json`; `special` is the one deduced rather than read.

**A bug's `tag` is a room's `bug_tag`.** That join is the only source anywhere for where an insect can be caught, and the room→location half is curated in `curated/aliases/game_rooms.json`.

**`"<..>"` means "derive from the name" and `"<n/a>"` means "has none".** Both are sentinels, not values.

**331 display names are shared** — fifteen chests are all "Basic Wood Chest". A shared name identifies nothing, so those keep a slug and the ambiguity is reported.

**`object_prototypes/crop.toml` is not the crop list, and there are three files, not one.** It holds everything that grows out of the ground, which is 26 crops and 67 forageables in the same table — the sprite prefix (`spr_crop_*` vs `spr_forage_*`) is the only thing separating them, and a single-entry `day_to_stage` means it is picked rather than grown. Fruit trees are in `object_prototypes/tree.toml` under a `fruit_data` subtable, and the wiki's Crops table has four of the seven you can plant. That third file is where Lemon, Peach and Pear were hiding while shipping as items with no availability at all. "104 game crops vs 58 wiki crops" is a red herring; the real gap was in the file nobody had opened.

**A tree is plantable only if a sapling item points at it.** `tree_plum_blossom` and `tree_coconut` fruit and nothing sells you one — they are wild, and matching trees to saplings by name would put a sapling in the app that no shop stocks. The join runs from the item's `sapling` field.

**`mystery_bag` declares `harvest = "apple"` and the game file's own comment says `# this is just a lie, for fun!`** It is the Magic Seed, which grows something random. A field can be deliberately false; a comment three characters away can be the only thing that says so.

**`artifacts.toml [locations]` is a room→pool map, and the pool names are the archaeology wing's set keys.** Room → pool → set members → `curated/aliases/game_rooms.json` is the complete "where do I dig this up" chain, stated end to end — it took 90 artifacts from no availability to full windows. The pools with no room (`oopart`, `mist`, `fish_trap`, the material sets) are placed by other stated facts or stay gaps; `ritual` is a name-match join and every window it produces is `inferred`.

**A seal is a quest, and the quest states its price.** `seals.toml` maps seal→quest; the quest stage's `requirements.supplied_items.items` is exact item ids and counts. The same structure prices the bridge and mill repairs. Extracted structurally (any stage with `supplied_items`), never by name list. Quest `description`s are prose — never read.

**Every game item carries its own `recipe` as internal ids** — 1,388 of them
(cooking, blacksmithing, milling, refinery, and 1,085 furniture waiting on
furniture ingestion), resolving 265/265 with no name matching. The wiki's
`Ingredients.ingredient` cell is **wikitext** (`[[File:…]] [[Apple]]`), and
reading it as a bare name is the bug that shipped 282 ingredient-less recipes
for five milestones. The wiki path survives as the no-extract fallback only.

**A perk's owning skill, tier and essence cost live in `ui/skill_menu/*.toml`**,
not in `perks.toml` (which is flat). The skills builder unions game perks the
wiki lacks — matched by *folded* name, because the wiki writes "Well Armed"
where the game writes "Well-Armed", and a hyphen must not conjure a second
perk.

**`fish.toml`'s `perk_artifact` is a perk-name *string*, not a flag.** Its `[default]` is `false`, so `bool()` silently nulled all ten artifact rules; only `str()` reads it right. The fished/dived artifact rules yield `unidentified_artifact` and the *rule id* is the artifact — `fishByItem` can never find them.

## Modelling rules

**Availability is an array of windows. Each window is an AND of constraints; the array is an OR.** A bug can be spring-in-town-at-night *and* all-season-in-the-mines-any-time. Never flatten two windows into one — it produces wrong answers on the flagship screen.

**Unknown does not exclude.** If `time` is `null` because we lack the data, the window matches every time and the result is badged "time unknown". Treating unknown as excluded makes the app quietly hide correct answers, which is worse than showing an unverified one.

**`null` means one of two different things and they must not be conflated:**
- *Not applicable* — mines have no weather. Expressed as `weather: null` + `weather_precision: "not_applicable"`.
- *Unknown* — we don't know yet. Expressed via `data_gaps: ["weather"]` on the record.

**Seasons and weather are always fully expanded arrays**, never an `"all"` magic string. Query code becomes a set intersection with zero special cases.

**An inference must never render identically to a fact.** Habitat expansion ("Pond" → three ponds) sets `confidence: "inferred"`, and the UI draws those pins hollow.

**Time windows may wrap midnight** (`to < from`). The build splits them into two non-wrapping intervals before shipping. Runtime code must never contain `if (start > end)`.

**Every record carries `former_ids[]` from day one.** When game files land and ids get rewritten, users' saved progress orphans without it. Not retrofittable.

## Layout

```
packages/schema/        @mistria/schema — Zod contracts. The availability model lives in src/availability.ts.
packages/pipeline/      extract/ enrich/ normalise/ build/ validate/
                        extract/ reads the game's TOML; build/game-facts.ts is what the builders see of it.
packages/sync-client/   the CRDT merge — imported by both the app and the Worker
apps/web/               the PWA (Vite + React + TanStack Router + Tailwind v4) — has its own CLAUDE.md
workers/sync/           Cloudflare Worker (Hono) — not started
sources/ curated/ data/ see the tier table above; curated/ has its own CLAUDE.md
docs/                   PLAN.md, research/, schema/, generated reports
```

## Commands

```
pnpm check            biome ci + tsc -b + vitest run
pnpm validate         zod + ajv + refint + vocab + licensing + determinism + coverage
pnpm extract          game files -> sources/game/     (never run in CI; needs .env)
pnpm enrich:cargo     fetch Cargo tables -> sources/  (never run in CI)
pnpm enrich:pages     fetch wiki pages -> sources/    (never run in CI)
pnpm assets:fetch     fetch sprites -> assets/game/   (never run in CI)
pnpm build:data       sources + curated -> data/
pnpm build:ship       data/ -> apps/web/public/data/
pnpm data:unresolved  print the curation to-do list
pnpm dev              the app, on localhost
pnpm build:web        production build (BASE_PATH sets the Pages base path)
```

The app has its own rules in [apps/web/CLAUDE.md](apps/web/CLAUDE.md) and its
design system in [docs/design-system.md](docs/design-system.md). The one that
bites hardest: **never write a leading `/` in a URL** — it works in dev and 404s
on GitHub Pages.

**`pnpm validate` must pass before any commit touching `data/`, `curated/`, or `sources/`.**

CI never touches the wiki — `sources/` is committed, so builds are hermetic and polite to wiki.gg. A weekly cron opens a refresh PR instead.
